# data_real: real, non-fiction datasets for testing (17 October 2026)

Built by `python -m chat22.data.build_real` (counts in `manifest.json`). A test folder beside the training data in use:
nothing here replaces the current mix until a test shows it is better. Only datasets already on disk were used (no
downloads until the 100M). Where text was chosen, documents with mostly British spelling were left out (modern American
English), and any document sharing a paragraph with our held-out test text was left out (1,361 removed).

## Audit: what our current datasets are

| dataset (in use) | where it comes from | real or invented |
|---|---|---|
| core text: Wikipedia | ENWIK9 (Wikipedia, 2006), cleaned | real (2006; mixed US/UK spelling) |
| core text: FineWeb | FineWeb-Edu web pages (educational, 2013-2024) | real, modern |
| core text: books | Project Gutenberg novels (Dickens, Austen, Melville...) | **fiction, 1800s English**: 13% of the rehearsal text, **42% of the long-document pool** (69% of documents over 32k characters) |
| core text: evidence | pairs of related Wikipedia / FineWeb paragraphs | real |
| core text: UltraChat | conversations generated by ChatGPT about real topics | machine-written, not fiction |
| core text: OASST | conversations written by human volunteers | real, human |
| core text: QQP | Quora question pairs | real, human |
| Q&A (data_qa) | Alpaca: instructions and answers written by GPT-3 | machine-written; some answers invented (poems, stories, made-up examples) |
| SQuAD (data_qa_squad) | Wikipedia paragraphs with crowd-written questions | real |
| dialogues (data_mt, data_chat22) | UltraChat + OASST, de-duplicated | mostly machine-written, part human |
| skills (data_skills) | generated personal facts, corrections, look-alikes | **invented on purpose**: conversation memory only |
| any-length conversations | real dialogues with planted invented facts | invented facts on purpose (conversation memory) |
| story worlds | generated characters and scenes | **fiction by design** |
| facts_pool (training look-alikes) | Alpaca + 20,001 invented skill facts + web pieces | mixed: invented and junk |

## Model-size folders and how much data each needs

Each size folder holds the files that depend on the size (plain text, long documents) and a `plan.json`; everything else is
in `shared/`. Sizes come from our results: real data at most about 2 passes (best near 1 for text), the 5M was still
improving on every kind at 26-33k steps, and the 100M is limited by compute on one RTX 3090. `python -m chat22.data.plan_real`
recomputes the table from the files.

| | 5M | 100M |
|---|---|---|
| core | runs/core_mt5m | runs/core_P100 (trained at 1,024 codes) |
| steps (floor / ceiling) | 30,000 / 48,000 (was 26-33k: real Q&A allows more) | 25,000 / 40,000 (estimate ~28-33 h) |
| windows at the ceiling | 768,000 | 640,000 |
| Q&A passes (292,675 real, incl. approved downloads) | 0.56 | 0.47 |
| skills passes | 1.12 | 0.93 |
| conversation passes | 0.37 | 0.31 |
| any-length passes (65,757 windows, real pool) | 1.28 | 1.07 |
| plain text passes | 0.95 (655 MB, unseen web) | 0.57 (915 MB, unseen web) |
| long documents passes | 0.50 (9,090 docs) | 0.24 (25,059 docs) |

Before any 100M run (see `100m/plan.json`): gradient accumulation in `chat22/train.py`, rope scaling for 2,048 codes, more
real Q&A (download approval), skills v5 and more any-length sessions for variety. No 100M training before the 5M study ends.

## How to train on it

`chat22/train.py --data-dir data_real/5m` reads each file from the size folder, then from `shared/` (defaults unchanged
and verified byte-identical). The exact command is in each `plan.json`. A test compares the model front by front with
variant A on the same suite.

## Updates 18-20 October: the store and the session pools the recipes use

The permanent store `shared/knowledge/knowledge_real.jsonl` now holds **311,010** real facts: Wikipedia leads 17,175 and
pieces 77,101, ARC science statements 120,000, OpenBookQA facts 1,326, and real Q&A memory facts 95,408 (from the approved
downloads). The 215,602-fact version is kept as `knowledge_real_v1_215k.jsonl`. Tests that need stored facts use its test
split (md5 of the question % 10 == 0, `chat22/tests/suite_v2.store_split`); training that reads the store (the twomem and
multi switches) uses only the other rows.

Any-length session pools (`chat22.data.build_v23 --only longconv --sessions 1250 --shard 0-3 --facts POOL --out-dir
shared/longconv_X --dialogues shared/convo/dialogues_train.jsonl [--vary]`), each copied into a recipe folder:

| folder | facts pool behind the sessions | used by | verdict |
| --- | --- | --- | --- |
| `5m_hybrid` | `shared/look/facts_pool_real.jsonl` (212,947 real facts) | round 4 | base for round 5 |
| `5m_mixed` | `facts_pool_mixed.jsonl` = real + 20,001 generated personal facts | round 5 and **C2b = BEST** | adopted (in `datasets/c2b_5m`) |
| `5m_mixed2` | `facts_pool_mixed2.jsonl` = mixed + all 50,937 Alpaca stored Q&A | round 6 | parked (told skills up, documents and story down) |
| `5m_mixedv` | mixed, with natural rewordings of 40% of the questions (`--vary`) | round 7 | parked (no wins, near-miss lost) |
| `5m_mixed3` | `facts_pool_mixed3.jsonl` = mixed + half of the Alpaca stored Q&A (25,648) | c2 (combined loop) | parked (story contradictions again) |

The generated personal facts are a training signal only: the store used for answering stays real-only.

The 100M plan in `100m/plan.json` was rewritten on 20 October for the C2b recipe (`docs/TRAIN_100M.md`); the `5m/` and `100m/` text and long-document folders belong to the real-data recipe that lost at 5M and are not used by C2b.
