5M Chat Model v2

A 5M model built from every result that held up this week: the best 5M core, the Q&A recipe, the 100,000-example skills data with rewriting, real conversations, and a new kind of training for remembering a whole conversation, all at a window twice as long. The experiment: four versions of the same model

Modern reasoning systems combine training targets that show the steps, checking answers before they are shown, tools for work the network should not do in its head, and training rewarded by outcomes. Each is tested here as a controlled step on the same model, so each one's gain is measured on its own. A and B train on exactly the same windows in the same order; only the extra target differs.

1. Training flow

Five kinds of window, all laid out exactly as the chat lays them out, sampled by share; each batch holds one kind and is padded only to its longest window.

training datamodeltests

2. Model structure

One network and two stores. The network reads and writes; the stores hold facts. Only the network is trained.

3. One chat turn

What happens between pressing Enter and the reply appearing.

How the 2,048-code window is shared

About 7,000 characters. The reply room is reserved first, so a long story never overruns; recent turns fill whatever is left, newest kept first.

≤ 400memory facts
≈ 950–1,500recent turns (as many as fit)

Older turns leave the window but stay in session memory until you quit or type /forget. With the default 400-code replies, roughly 5–10 recent exchanges stay in the window, depending on their length.

Risks, and where each would come from

Wait grows with the window

Reading the window is the cost before the first word; it grows with the conversation. Writing stays fast because of the KV cache, but each step also attends to the whole window.

Positions past 2,048

The core trained at 1,024, the stage at 2,048. Text past the trained window is untested ground: rotary positions continue, but the model has never seen them, so quality is expected to drop there.

Session memory misses

A scrolled-out detail comes back only if the lookup finds it. Rewording ("my sibling" for "my sister") can miss; this is the retrieval weakness K2 is meant to fix.

5M knowledge

Conversation and memory skills do not add general knowledge: without memory the 5M network still writes fluent nonsense (rated 7.9–9.9). Stories will be short and simple.

Long replies drift

Small models repeat and lose the thread over hundreds of codes. The repeat block (no 3-code phrase twice) helps; the story test measures the rest.

Mixing five kinds of data

Each share takes steps from the others. The chat probe and report card check that Q&A and language were not traded away.

The verifier is only as good as its check

It prefers answers whose words are found in the evidence. That catches "Jakarta" beside a Tokyo entry, but not a correct rewording that uses new words, and it multiplies the answer time by the number of candidates. Off for replies without evidence (stories, chat).

Self-training at 5M

Outcome-rewarded training worked at billions of weights; our one earlier try (math, 5M) gained 1.5 points. One round on the model's own correct answers may change little; D measures it.

Tools are narrow

The calculator reads "12 plus 30", "7 x 8" and "have three apples ... eat one"; anything worded otherwise falls back to the network. It ignores phone numbers, codes and times on purpose.

Streaming

Yes. Replies appear word by word in the terminal as they are written, in conversation mode. The last few characters are held back until the reply ends, so the stop markers never show. When the verifier checks several candidates (only when memory or a tool supplied evidence), the chosen reply appears word by word once the check is done, a fraction of a second later on the GPU. Stories and ordinary chat stream as they are written. The line under each reply shows how full the window is, how many turns it holds, whether an earlier turn was recalled from session memory, any tool used, and the first-word wait. Settings: CHAT_VERIFY (3 by default, 0 to turn off), CHAT_TOOLS, CHAT_REPLY_CODES.
