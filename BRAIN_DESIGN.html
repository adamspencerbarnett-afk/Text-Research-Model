A brain-inspired version of the model: fast memory, a slow learner, skill circuits and sleep

Research concept and direction by Adam Barnett. This is a design for a follow-on project, to begin once the current research (the scale, Q&A, reading and reasoning screens) has finished. It is theory built on measured results: every number below comes from runs already logged in docs/RUN_LEDGER.md and docs/ENCODER_RESEARCH_PLAN.md, and every proposed change has a test that can prove it wrong.

Status proposal, not started Depends on current research finishing Hardware one RTX 3090, 64 GB

1. The idea in one paragraph

Brains learn new facts after one exposure without forgetting old skills, use very little energy, and improve while asleep. They do this with two learning systems that work together: a fast memory that records experiences at once (the hippocampus) and a slow learner that absorbs general knowledge gradually (the neocortex), plus specialised circuits for particular skills and a sleep phase that moves important memories from the first system into the second. Conventional language models have only the slow learner, so every new fact needs retraining and every answer runs the whole network. Our model already has a working fast memory and a small slow learner. The proposal is to complete the picture: add small trainable skill circuits, a way to notice its own gaps, and a safe sleep cycle, so the system grows smarter from its own use while staying small, fast and cheap to run.

2. How the current model works

Each part below links to its exact specification (spec opens it here); all of them are collected in section 9, which is enough to rebuild the current best model from scratch.

  1. Compilerspec (deterministic, no learning). Turns text into codes of about 3.5 bytes each and back, exactly. The same compiler serves training and conversation, so stored items always have stable keys.
  2. Exchange memoryspec (no learned parameters). Every question and answer is stored under a key made from the question's content words. A new fact is one table entry: added in about a millisecond, answerable immediately, deletable, inspectable.
  3. Count tablesspec (no learned parameters). Exact counts of which code follows which, rebuilt from text in seconds. They let the model learn by reading: one Austen novel added to the counts improved prediction of another Austen novel with no training.
  4. Network corespec (learned). A small Transformer, trained first on 286 MB of books and Wikipedia, then on question-and-answer texttraining. The copy headspec is a learned pointer that reads the retrieved exchange and carries its answer into the reply.
  5. Trust headspec (learned, one small layer). For every word of the reply it weighs the network, the tables and the copy head by their confidence.
  6. Answeringspec: retrieval, the window, greedy decoding with repeat blocking, the calculator and its answer check.

The point of the mapping is not to copy biology. Two properties of the brain explain most of its efficiency, and both are achievable here. First, most knowledge is looked up or computed only when needed, not pushed through every connection for every thought. Second, learning happens at two speeds, so new information is usable at once and becomes general skill later, without the cost of retraining everything.

4. The adaptations, each with its reason and test

4.1 Memory that recalls from a partial cue

Brain role
Hippocampal pattern completion: a fragment of a memory brings back the whole.
Change
A second, learned key beside the literal one. The core's own representation of the question is stored with each memory and searched by similarity. The literal key stays for exact and inspectable recall; the learned key catches rewordings and synonyms. Plus the copy head trained on reworded questions (R0b, running now).
Why
The chat probe: the right memory existed for "graphics card" and "GPU", and for reworded cooking and virus questions, but was either not found or not used.
Test
Reworded and synonym sections of the probe battery from 1/10 to at least 6/10, with no loss on verbatim questions.

4.2 Skill circuits: small adapters on a shared core

Brain role
Specialised circuits that share the same cortex: number sense, conversation, reading.
Change
Small extra weight sets (1–5% of the core each) attached beside each layer and trained for one skill while the core stays frozen. One for setting up arithmetic, one for conversation, one for reading comprehension, one per domain as needed. Each is a separate file: versioned, testable, removable.
Why
Retraining the whole core for one skill risks damaging others, and every core size scored 0–2% on arithmetic set-up. A skill needs its own circuit and data. A frozen core keeps general language for every adapter to build on, so each adapter can be small and quick to train.
Test
A math adapter raises new-problem accuracy above the frozen-core baseline while the conversation probe score stays within one point. Compared with fine-tuning the whole core on the same data and time.

4.3 Choosing the circuit: the trust head as router

Brain role
Neuromodulation and attention: engaging the right circuits for the task.
Change
The trust head already weighs network, tables and memory per word. Extend it to weigh adapters too, from the question's representation and each adapter's confidence. Only the chosen adapters run, so cost grows with the question, not with the number of skills.
Why
Without routing, every adapter runs on every question and they interfere. With it, the system is a set of small experts behind one front door.
Test
On a mixed question set, the router picks the adapter a human would pick at least 90% of the time, and mixed-set accuracy is within two points of giving each question its correct adapter by hand.

4.4 Noticing its own gaps: the surprise signal

Brain role
Prediction error: the brain learns most from what it did not expect.
Change
Every answer logs the signals we already have: the trust head's confidence, whether memory found anything and how close it was, whether the calculator rejected the stated answer, whether a check failed. Failures are grouped by kind. When a kind accumulates (for example, a hundred low-confidence arithmetic questions), the system proposes an adapter for that kind and the data to train it.
Why
Training "as needed" requires knowing what is needed. On GSM8K the calculator already replaced 628 wrong stated answers in one run; that is a gap signal going unused.
Test
Gap detection agrees with hand grading on the probe battery at least 80% of the time; an adapter trained on detected failures beats an adapter trained on a random sample of the same size.

4.5 Sleep: folding memory into the network

Brain role
Consolidation during sleep: replay strengthens what matters; the rest fades.
Change
In idle time, a copy of the live model trains on the memories used most often (and their rewordings), mixed with a sample of its earlier training data so old skills are rehearsed. Facts that are now answered without memory may be marked as consolidated; one-off facts stay in memory only. A pruning policy retires memories that are never used, within a size budget set per device.
Why
Memory answers exact wording well and rewording badly; the network generalises over wording. Consolidation gives frequently used knowledge both. It also keeps memory from growing without limit on small devices.
Test
After sleep on 500 added facts: at least 70% answered correctly with memory switched off, and reworded versions improved; probe battery on old knowledge no lower than before.

4.6 Updating while people use it

Brain role
None needed; this is engineering. The brain never stops; a service must never stall.
Change
The live model is a fixed version. New facts go into memory instantly (a table entry; no weights change). Adapters and sleep train on copies. A candidate goes live only after gates: no probe section worse, consolidated facts answered without memory, speed and size within limits. The switch is a pointer change: new conversations use the new version, current ones finish on the old one, and rollback is the same switch.
Why
Users must never see a half-trained model or a pause.
Test
Run a chat session continuously while a sleep cycle and an adapter publish happen; no reply fails or slows by more than 10%, and rollback restores the previous answers exactly.

The proposed architecture

5. Goals and objectives

The project goal: a model that runs on one consumer GPU, answers what it knows as reliably as a much larger model, learns a new fact in seconds and a new skill in minutes, improves from its own use without retraining from scratch, and never interrupts the person using it. Each stage below has a pass condition that can be measured with the tools already in the repository (the probe battery, the run ledger, the Q&A scorers).

B0
Baseline frozen. The winning design from the current research (core size, data mix, copy head) is saved as the starting point, with its probe battery score and Q&A scores recorded.
Pass: one checkpoint and one result file that every later stage compares against.
B1
Partial-cue recall. Learned key beside the literal key; copy head trained on rewordings.
Pass: probe reworded + synonym sections ≥ 6/10 each; verbatim unchanged.
B2
First skill circuit. An arithmetic set-up adapter on the frozen core, trained on GSM8K and SVAMP.
Pass: new-problem accuracy at least double the frozen-core baseline; conversation probe within one point; adapter under 5% of core size.
B3
Router. Three adapters (arithmetic, conversation, reading) chosen by the trust head.
Pass: router agrees with hand choice ≥ 90%; mixed-set accuracy within two points of hand routing; per-reply cost grows by less than 20%.
B4
Gap detector. Failure log with grouping and an adapter proposal.
Pass: ≥ 80% agreement with hand grading; an adapter trained on detected failures beats one trained on a random sample of equal size.
B5
Sleep. Consolidation of used memories with rehearsal, plus pruning to a size budget.
Pass: ≥ 70% of 500 added facts answered with memory off after one sleep; rewordings improved; old-knowledge probe not lower.
B6
Live updating. Versioned serving with gates, swap and rollback, exercised during a continuous chat.
Pass: no failed reply; latency within 10%; rollback restores previous answers exactly.
B7
Comparison. The full system against a conventional model of 10–100× its learned parameters, on the same questions.
Pass: on knowledge it holds, accuracy within five points of the larger model at a tenth of the compute per reply or less; plus the abilities the larger model lacks (instant facts, deletion, inspection).

Where it will not beat a large model, stated plainly. Open-ended reasoning about things it has never seen, broad world knowledge it was never given, and fluent long writing all depend on a large slow learner, and a 5M core will not match one. The design wins where knowledge can be stored, looked up, checked or routed to a skill, which covers a large share of practical use (assistants for a domain, a company's documents, personal knowledge, devices without a data centre). The test in B7 is designed to show the size of that share honestly, including where the larger model is better.

8. What must finish first, in the current research

  • The core size: the fair 19M comparison (R1f, queued) decides 4.7M or 19M as the shared core.
  • Partial-cue recall: R0b (training on rewordings, running) is the first half of B1.
  • Reading comprehension (R2b, queued) and the capability map across task types, which tell us which skills need their own circuits.
  • Conversation data, so the conversation adapter has something to learn from.
  • The run ledger and probe battery as the measuring tools for every stage above (in place).

When those are in, B0 is a matter of freezing the winner, and the project can start with B1 and B2, which together take about a day of runs on the current machine.

Compiler v0 text to codes and back, exactly

Files

compiler/compiler_v0.py (reference: scan, fit, learn_pieces, Encoder, Dictionary), compiler/native/cv0.cpp (fast encoder, must be byte-identical), tests in compiler/test_compiler_v0.py.

ID layout:   0..255 = single bytes (fallback)   256 = CAP   257 = UPPER   258.. = dictionary entries in file order

scan(text):  split into units, left to right, first rule that matches wins (bytes regex):
               " [A-Za-z]+"  |  "[A-Za-z]+"  |  " +(?= [A-Za-z])"  |  " +"  |  "\n+"  |  "\t+"  |  any single byte
             concatenating the units gives the text back exactly; digits are single-byte units

fit(train_texts, vocab = 8192, phrases = 0, case_flags = off, min_count = 2):
  counts = number of times each unit of length >= 2 occurs in the training text
  words  = each distinct unit as a list of single bytes, weight = its count (sorted, for determinism)
  repeat until (vocab - 258) entries exist:
      take the adjacent pair (a, b), len(a) + len(b) <= 32, with the highest total weight;
          a pair is keyed by at_start = (it is at position 0 of its unit)
      stop if that weight < min_count
      new entry: kind "S" (start piece) if at_start else "C" (continuation piece), bytes a + b
      replace that pair with the merged symbol everywhere it occurs with the same at_start
  dictionary file: "compiler-v0 dictionary", "version 1", "case_flags 0", "max_phrase_units 1",
                   "entries N", then one "S\tbytes" or "C\tbytes" line per entry (escaped)
  dictionary hash = FNV-1a 64-bit of that file

encode(text):
  for unit in scan(text):
      pos = 0; table = START pieces
      while pos < len(unit):
          L = longest length in 32..2 such that unit[pos : pos + L] is in table
          if none: emit byte id unit[pos]; L = 1        else: emit that entry's id
          pos += L; table = CONTINUATION pieces
decode(ids) = concatenation of each id's bytes      (lossless by construction)

ID file: 24-byte header (b"CV0I", version 1, id width 2 or 4, 2 pad bytes, dictionary hash, count),
         then the ids as little-endian uint16 (uint32 above 65,536 ids)

The best model's dictionary is models/v0_8k_plain_corpus_v2.cv0d: 7,934 entries, 8,192 IDs, hash 3febecd65a1a77ff, fitted on the corpus v2 training stream, no case flags, no phrases. About 3.5 bytes of text per code.

Check: 34 contract tests pass, including round trips on all 256 byte values and the native/Python parity test; a refit on the same training text gives the same hash.
Count tables (M1) what usually comes next, exact and rebuilt in seconds

Files

compiler/experiments/train_lm.py: NgramTable, table_features; used inside LM.nll, LM.mixed_logits.

build(codes, order, topk = 64):                    # every code < 2^21
  k = order - 1
  context(i) = codes[i .. i+k-1] packed 21 bits each; follower(i) = codes[i+k]
  count every distinct (context, follower) pair
  per context: followers sorted by count, descending; keep the first topk (ragged arrays: offsets, ids, counts)
               total = count of all followers, kept or not
  contexts sorted, so lookup is a binary search; arrays moved once to the GPU and cached there

lookup at position t: context = the k codes ending at t (incomplete at the start of the window = not found)
  found     -> follower ids, counts, total      not found -> ids -1, counts 0, total 0

probability of the target y at t:
  c = count of y among the kept followers; kept = sum of kept counts
  in training only (leave-one-out, mandatory): c = c - 1 if c > 0;  kept = kept - 1 if total > 0
  p_table(y) = c / kept  if kept > 0  else 0
confidence features, 3 per table (to the trust head):
  log(1 + total - LOO),  share of the top follower,  entropy in bits of the follower shares

orders used: 2 and 3; counted on the training codes only (in stage 1 the last 2% is validation and not counted)
Check: test_ladder.test_ngram_table_counts_and_lookup and the leave-one-out test; the GPU lookup was verified identical to the earlier padded CPU lookup on four table sizes.
Network core (M3) a small pre-norm Transformer with tied embeddings

Files

compiler/experiments/train_lm.py: Block, LM (embed, hidden, nll).

parameters: E (vocab x width, shared by input and output), P (ctx x width), L blocks, final LayerNorm
init:       every Linear weight and both embeddings ~ Normal(0, 0.02); biases 0

embed(x)  = E[x] + P[0 .. T-1]
block(h):                                         # repeated L times
  q, k, v = split(W_qkv · LN1(h))                 # W_qkv: width -> 3·width, no bias; H heads of width/H
  h = h + W_o · causal_scaled_dot_product_attention(q, k, v)        # W_o no bias
  h = h + W_2 · GELU(W_1 · LN2(h) + b_1) + b_2    # W_1: width -> 4·width
hidden(x) = LN_f(block_L(... block_1(embed(x))))
network distribution at t = softmax(hidden_t · E^T)

sizes used:  0.8M core: width 128, 4 layers, 4 heads      4.7M: 256, 6, 8 (the best model)
             19M: 448, 8, 8                               49M: 640, 10, 10       context 256 codes
core parameters ~ 12 · layers · width^2  (+ vocab · width for E, + ctx · width for P)

Exchange memory (M2) question key to stored answer, exact and nearest

Files

compiler/experiments/m2_qa.py: STOP, words_of, ExchangeMemory (key_of, add, retrieve, exact_hit, similarity_keys).

STOP = a fixed list of 117 English function words and instruction verbs (a, the, of, ..., write, describe, explain, list, name, ...)
words_of(text)   = [unit stripped of its space, lower-cased  for unit in scan(text)  if it is letters only]
key_of(question) = the set of words_of(question) that are not in STOP and longer than one letter

add(question, answer):
  i = number of stored exchanges; store (question, answer) and its key
  exact[key] = i  if key not already present       (the first exchange with a key wins)
  for w in key: index[w].append(i); df[w] += 1

idf(w) = ln((1 + N) / (1 + df[w]))                 N = stored exchanges

retrieve(question):
  key = key_of(question)
  for w in key with df[w] <= 5% of N:              # very common words do not vote
      for i in index[w]: score[i] += idf(w)
  similarity(i) = score[i] / (sum of idf(w) over key + sum of idf(w) over key_i - key)
  return the exchange with the highest similarity

used for answering: exact[key_of(question)] if present (similarity 1), else retrieve(question)
Check: stored questions return their own answer 99% exactly (the 1% are different questions with the same key); a pair added after training is found at once.
Copy head a learned pointer into the retrieved exchange

Files

compiler/experiments/m2_qa.py: V2LM.extra_parts, V2LM._span.

inputs: hidden states h of the window, codes x, span S (positions of the retrieved exchange;
        with --copy-question also the current question's positions)

allowed(t, j) = S[j] and S[j+1] and j < t        # j's follower lies in the span, and j is strictly earlier:
                                                  #   pointing at t itself would reveal the target
score(t, j)   = (W_q · h_t) · (W_k · h_j) / sqrt(width)        # W_q, W_k: width x width, no bias, Normal(0, 0.02)
a(t, .)       = softmax of score over the allowed j            # a row with nothing allowed is all zeros
p_copy(y at t) = sum over j of a(t, j) · [x[j+1] = y]          # copying a passage is a walk along it
confidence features (2): max over j of a(t, j);  entropy in bits of a(t, .)
parameters: 2 · width^2 (131k at width 256)
Check: with the copy head, network answers to stored questions rise from 0.13 to 0.79–0.88 word F1; a test with a self-matching window must give zero copy probability for the target (the leak test).
Trust head mixes the sources, word by word

Files

train_lm.LM.nll / mixed_logits (network + tables), m2_qa.V2LM.nll / mixed_logits (+ copy head, optional evidence table and similarity input).

sources at position t:   network (softmax of the core),  bigram table,  trigram table,  copy head
features(t) = [ h_t,                                   # the core's state
                3 confidence features per table,       # see count tables
                2 confidence features of the copy head,
                retrieval similarity  (only with --sim-feature) ]
w(t) = softmax(W_mix · features(t) + b_mix)            # one Linear layer; one weight per source; init Normal(0, 0.02), bias 0
p(y at t) = sum over sources s of w_s(t) · p_s(y at t)
loss = - log max(p(y at t), 1e-9)                      # training and scoring use the same formula
Check: training and generation give the same target probability at the last position (unit check in the session log of 9 October).
Training stage 1 on books and Wikipedia, stage 2 on Q&A

Files

Stage 1: compiler/experiments/scale_run.py calling train_lm.run. Stage 2: compiler/experiments/m2_qa.py (sample, batch, training loop).

STAGE 1  (core 256w 6L 8h, compiler + count tables, corpus v2 + Wikipedia)
  stream = encode(training stream); validation = its last 2%; tables counted on the first 98%
  each step: 64 random windows of 257 codes; inputs = codes 0..255, targets = codes 1..256
  loss = mean over all positions of the trust-head loss (tables with leave-one-out)
  AdamW: peak lr 1e-3, betas (0.9, 0.95), weight decay 0.1 on matrices only
  lr(step) = peak · min(1, step / 100) · (0.1 + 0.9 · (1 + cos(pi · elapsed / budget)) / 2)
  gradient norm clipped to 1.0; bfloat16 autocast in the step; scores in full precision
  budget 1,800 s on one RTX 3090 = 42,538 steps, 2.2 GB of text seen  ->  models/core_5M_stage1_books_wiki.pt

STAGE 2  (Q&A design, Alpaca; dictionary and core from stage 1)
  load every stage-1 tensor whose shape matches; copy head and trust head start new
  memory = all training exchanges; tables = counts over all training exchange codes
  window for exchange i (257 codes):
      retrieved = i itself with probability 0.5 (copying is right), else its nearest other exchange
      [ last 110 codes of the retrieved exchange ] + [ the code of "\n\n" ] + [ exchange i, first 145 codes ] + padding
      loss mask = exchange i's codes only (with --loss-answer-only: its answer only)
      --perturb-self p: of the self windows, a share p have the retrieved question reworded (words dropped 20%,
                        replaced 10%, neighbours swapped 15%) and the similarity recomputed
  each step: 32 windows; AdamW lr 1e-3 constant, betas (0.9, 0.95), decay 0.1 on matrices; clip 1.0
  validation every 60 s: bits per byte on 120 held-out exchanges with their nearest exchange retrieved
  --patience n: stop after n evaluations without improvement; keep the best weights
  best model: 600 s, 15,565 steps, seed 2 -> models/qa_best_5M.pt
Check: stage 2 from the stage-1 checkpoint lands within seed noise of seen 0.79–0.88 F1 and 47–52% exact (greedy), validation about 1.0 bits per byte.
Answering from a question to a reply

Files

m2_qa.QAEngine.ask (chat) and the answer function inside m2_qa.main (scoring); repeat_banned, evaluate_tail, final_number.

ask(question):
  retrieved, similarity = exact hit (1.0), else nearest by retrieve(), else none
  window = [ last 110 codes of the retrieved exchange ] + [ "\n\n" ] + encode("User: " + question + "\nAssistant:")
  span   = the retrieved codes (+ the question's codes with --copy-question)
  repeat up to 120 codes:
      scores = log of the trust-head mixture at the last position of window[-256:]
      forbid codes never seen in the training text
      forbid any code that would complete a 3-code phrase already in the reply          (repeat blocking)
      next = the code with the highest score                                            (greedy)
      append next
      if calculator and next is "=" and the reply ends in "a op b =" (op in + - * x /):
          append the computed value (integer if whole, else 2 decimals) and forbid a digit right after it
      stop if the reply contains "\nUser" or an invented "\nAssistant:"
  reply = decode(the new codes), cut at "\nUser" / "\nAssistant:"
  calculator rule 2: the reply's final "Answer: N" must equal a computed value, else it is replaced by the last one
add(question, answer) = memory.add: the fact is answerable on the next question, no training
Check: the 32-question probe battery (chat_probe.py) gives 35/64 with memory and 1/64 without on models/qa_best_5M.pt.
Scoring how every number in the ledger is measured

Files

m2_qa.f1, num_exact, the groups in m2_qa.main; train_lm.total_bits, eval_file; chat_probe.py; run_ledger.py.

bits per byte (language modelling) = sum of -log2 p over every code of a file / bytes of the file
                                     (windows of 256 codes, context reset at each window)
word F1(reply, reference): P = shared words / reply words, R = shared words / reference words (words_of, with counts)
                           F1 = 2PR / (P + R); 0 if nothing is shared
exact = reply bytes equal reference bytes;   num_exact = final "Answer:" number equal (GSM8K)
held-out Alpaca split in half (seed): half for evaluation, half added to memory after training
groups:  seen       = 200 training questions (memory path) / 60 (network path, own exchange retrieved)
         reworded   = held-out questions whose nearest key has similarity >= 0.5
         new        = the other held-out questions, nearest exchange retrieved
         no memory  = 60 held-out questions with nothing retrieved
         added      = held-out pairs put into memory after training, then asked
seed noise on the 60-answer groups: about +-0.07 F1

reload a Q&A model (QAEngine):
  args = checkpoint["args"]; dictionary = args.dict; training text = args.data + "/train/qa_train.txt"
  memory  = add every training exchange
  tables  = NgramTable(encode(training text), 2 and 3, args.topk)
  model   = V2LM(shape and flags from args), load state_dict
  count tables and memory are never stored: they are rebuilt from the text in seconds
