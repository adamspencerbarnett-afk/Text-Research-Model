A brain-inspired version of the model: fast memory, a slow learner, skill circuits and sleep

Research concept and direction by Adam Barnett. This is a design for a follow-on project, to begin once the current research has finished. It is theory built on measured results: every number below comes from runs logged in docs/RUN_LEDGER.md and docs/ENCODER_RESEARCH_PLAN.md, and every proposed change has a test that can prove it wrong. Section 9 is a reconstruction specification of the current best model, written from the code, so the model can be rebuilt from this page.

Status proposal, not started Best model chat22 variant A (runs/chat22/v24a_s1.pt), 17 Oct Before this starts the 5M study and the merged model; 50M / 100M cores kept Hardware one RTX 3090, 64 GB

1. The idea in one paragraph

Brains learn new facts after one exposure without forgetting old skills, use very little energy, and improve while asleep. They do this with two learning systems that work together: a fast memory that records experiences at once (the hippocampus) and a slow learner that absorbs general knowledge gradually (the neocortex), plus specialised circuits for particular skills and a sleep phase that moves important memories from the first system into the second. Conventional language models have only the slow learner, so every new fact needs retraining and every answer runs the whole network. Our model already has a working fast memory and a small slow learner. The proposal is to complete the picture: small trainable skill circuits, a way to notice its own gaps, and a safe sleep cycle, so the system grows smarter from its own use while staying small, fast and cheap to run.

2. How the current model works

Each part below links to its exact specification (spec opens it here); all of them are collected in section 9, which is enough to rebuild the current best model from scratch.

  1. Compilerspec (deterministic, no learning). Turns text into codes of about 3.5 bytes each and back, exactly. One dictionary per training mix, fitted on that mix; the same compiler serves training and conversation, so stored items always have stable keys.
  2. Exchange memoryspec (no learned parameters). Every question and answer is stored under a key made from the question's content words; a new fact is one table entry, added in about a millisecond, answerable at once, deletable, inspectable. An optional learned key (a small head on the core) can be combined with the literal one.
  3. Count tablesspec (no learned parameters). Exact counts of which code follows which, rebuilt from text in seconds. They help a small core and hurt a larger one, so they are used in the Q&A stage and in the 5M core, and left out of the 50M core's training.
  4. Network corespec (learned). A small Transformer trained in two stagestraining: first on 0.3-2.3 GB of clean modern text, conversation, evidence pairs and worked mathdata, then on question-and-answer text with a gentle recipe that keeps what stage 1 built. The copy headspec is a learned pointer that reads the retrieved exchange and carries its answer into the reply.
  5. Trust headspec (learned, one small layer). For every word of the reply it weighs the network, the tables and the copy head by their confidence.
  6. Answeringspec: retrieval, the window, greedy decoding with repeat blocking, an end-of-answer code, the calculator and its answer check.
  7. Measuringscoringreport card and practisingself-training: how every number here is obtained, and the verified self-training loop for arithmetic.

The point of the mapping is not to copy biology. Two properties of the brain explain most of its efficiency, and both are achievable here. First, most knowledge is looked up or computed only when needed, not pushed through every connection for every thought. Second, learning happens at two speeds, so new information is usable at once and becomes general skill later, without the cost of retraining everything.

4. The adaptations, each with its reason and test

Stability rules (added 17 October). Every adaptation below obeys these, because each one answers a failure we have seen:

  1. The live model never trains. All learning happens on a copy; the copy goes live only through the gate.
  2. The gate is the full test suite, front by front against the best earlier model (within two standard errors), on two seeds where training is involved; never a training curve alone.
  3. Replay the whole mix. Any training (sleep, practice, a circuit) includes every proven kind at its measured share; nothing is trained alone.
  4. One change per cycle, so the gate can say what helped and what hurt.
  5. Precise memory over generous memory: a short block of items that pass a calibrated bar, newest value first, an empty block when nothing passes.
  6. Real facts only in the semantic store and in the weights; personal and invented material stays in conversation memory (deletable, never consolidated into shared weights).
  7. Rules first; a learned gate filters only after it meets its precision bar on held-out data.
  8. Resource guards on everything unattended: a GPU memory cap per job, one background training at a time, a stall watch, training floors so nothing stops on noise.

4.1 Memory that recalls from a partial cue

Brain role
Hippocampal pattern completion: a fragment of a memory brings back the whole.
Change
A learned key beside the literal one: the frozen core's mean state over the question, through a small trained head, as a unit vector; retrieval ranks by literal + learned similarity. Built (K1, --key-head; K2 in session 32).
Revised 17 Oct
Finding is solved (100% on single facts, distractors and corrections in the retrieval study); choosing is the hard part. The memory is now three layers: (1) conversation memory (episodes, any length), (2) a fact table built from statements (who, attribute, value, turn, history; links between names and relations), (3) the permanent store of real facts. A question is read first (who and what is asked), answered from the fact table when the match is exact, and otherwise from candidates that pass a calibrated bar; nothing passes, nothing is shown. The learned key remains the way to improve candidates (K2 in place of MiniLM), not the way to choose.
Why
The chat probe: the right memory existed for "graphics card" and "GPU" but was not found.
Evidence so far
Trained on 134k Quora rewordings: 75.2% at rank 1 alone and 77.7% combined, against 74.3% for the literal key; on our Alpaca Q&A, no gain (out-of-domain training pairs). The 50M core's own state already finds 58% of rewordings (5M: 51%).
Test
Retrain the head on in-domain pairs (rewordings of our own stored questions) on the 50M core; reworded and synonym sections of the probe from 2/5 to at least 4/5, no loss on verbatim questions. Engine-level pass (retrieval study): right item in the block at least 99% (one fact, distractor, correction), look-alike and outdated values under 5%, never-told blocks clean above 90%, 1-4 items per block.

4.2 Skill circuits: small adapters on a shared core

Brain role
Specialised circuits that share the same cortex: number sense, conversation, reading.
Change
Small extra weight sets (1-5% of the core each) attached beside each layer and trained for one skill while the core stays frozen. One for arithmetic set-up, one for conversation, one for reading comprehension, one per domain as needed. Each is a separate file: versioned, testable, removable.
Why
Full fine-tuning at a normal rate erased what stage 1 built (S2a series); every core size scored low on choosing arithmetic steps; a skill needs its own circuit and data.
Revised 17 Oct
Measured at 5M (session 31): LoRA adapters on the frozen core lost more than 40% of the network-alone answers, and one mixed stage won. So the default is the mixture, and a circuit is an option that must earn its place: tried first on the 50M / 100M core, trained with the whole mix replayed beside it, and kept only if the full suite holds on every front. Maths is paused (12 October), so the first circuit is reading documents, the largest open gap (about 30% since v2.2 against 80% in v2.1).
Test
A reading adapter on the frozen 50M core beats the mixed-stage baseline on document questions (window and memory) with no suite front lower than the baseline by more than two standard errors; adapter under 5% of core size. If it fails, the skill goes back into the mixture at a higher share.

4.3 Choosing the circuit: the trust head as router

Brain role
Neuromodulation and attention: engaging the right circuits for the task.
Change
The trust head already weighs network, tables and memory per word. Extend it to weigh adapters too, from the question's representation and each adapter's confidence. Only the chosen adapters run.
Why
Without routing, every adapter runs on every question and they interfere.
Revised 17 Oct
The first router to build is the memory gate, not an adapter router: whether to use memory at all, and which items. Measured: a stricter gate raised single facts 43% → 74% with no retraining; the rule-based fact table beat a learned judge that was not yet precise. Learned routing comes after rules, behind a precision bar.
Test
On a mixed question set, the router picks the adapter a human would pick at least 90% of the time, and mixed-set accuracy is within two points of hand routing. Any learned filter: at least 95% precision on held-out pairs at a recall that loses no suite front.

4.4 Noticing its own gaps, and practising them

Brain role
Prediction error, and practice with feedback.
Change
Every answer logs the signals we have: trust-head confidence, retrieval similarity, calculator rejection, check failures. Failures are grouped by kind; where an exact checker exists, the kind is practised by verified self-training (built: star.py); elsewhere an adapter is proposed with the data to train it.
Why
The calculator replaced 1,188 wrong stated answers in one GSM8K run: a gap signal. Practising on checked self-solutions raised new-problem accuracy 2.5% → 4.0% in two rounds.
Revised 17 Oct
The strongest gap signal is now the grounding score: for every answer, right, copied a wrong memory, refused although told, or invented. The two failure directions (refusing and inventing) trade against each other, so practice targets the balance: auto-graded answer pairs (answer over refusal when the fact was told; "I don't know" over invention when it was not; the newest value over the old one), trained on a copy with the whole mix replayed. This is the merged model's planned grounding stage.
Test
Gap detection agrees with hand grading on the probe battery at least 80% of the time; practice on detected failures beats practice on a random sample of equal size; refusals of told facts fall without invented answers rising.

4.5 Sleep: folding memory into the network

Brain role
Consolidation during sleep: replay strengthens what matters; the rest fades.
Change
In idle time, a copy of the live model trains on the memories used most often (and their rewordings), mixed with stage-1 text so old skills are rehearsed (30% rehearsal is measured to protect the core). Facts answered without memory afterwards may be marked consolidated; one-off facts stay in memory only. A pruning policy retires unused memories within a size budget.
Why
Memory answers exact wording well and rewording badly; the network generalises over wording.
Revised 17 Oct
Replay is the whole mix at its proven shares, not only stage-1 text: anything left out fades (v2.3). Only real facts from the permanent store are consolidated; personal and invented conversation facts stay in conversation memory, where they can be corrected and deleted. The cycle runs to a floor of steps (no stopping on noisy checks), changes one thing, and goes live only through the full suite. A fact counts as consolidated only if answered with memory off and memory answers do not get worse.
Test
After sleep on 500 added real facts: at least 70% answered correctly with memory switched off, rewordings improved, no suite front lower than before (two standard errors), conversation-memory recall unchanged.

4.6 Updating while people use it

Brain role
None needed; this is engineering. A service must never stall.
Change
The live model is a fixed version. New facts go into memory instantly. Adapters and sleep train on copies. A candidate goes live only after gates (no probe section worse, consolidated facts answered without memory, speed and size within limits); the switch is a pointer change, current conversations finish on the old version, rollback is the same switch.
Revised 17 Oct
Background training shares the GPU with serving, so every background job runs under a hard GPU memory cap (an error, never paging), one at a time, with a stall watch. Measured: one 5M training needs about 11 GB of GPU cache; three side by side stalled the card within minutes.
Test
A continuous chat session through a sleep cycle and an adapter publish: no reply fails or slows by more than 10%; rollback restores the previous answers exactly; GPU memory never above its cap.

The proposed architecture

5. Goals and objectives

The project goal: a model that runs on one consumer GPU, answers what it knows as reliably as a much larger model, learns a new fact in seconds and a new skill in minutes, improves from its own use without retraining from scratch, and never interrupts the person using it. Each stage has a pass condition measurable with the tools already in the repository (probe battery, run ledger, Q&A scorers, core report card).

B0
Baseline frozen. Revised 17 Oct: the baseline becomes the merged chat model (one mixed stage + grounding stage, two seeds) with search engine v2 and the real-facts store, measured on the full chat22 suite (39 fronts). Today's best single model: variant A, best or tied-best on 26 of 39 fronts. Earlier baseline, kept for history: Done at 5M: models/qa_best_5M_512.pt (stored 0.89 F1 / 56-63% exact, added 0.86-0.88, reworded 0.26-0.30, new 0.27-0.29, network alone 0.23-0.24, probe 20-23/32, two seeds). At 50M (first Q&A stage, 60% of its steps): stored 0.89 / 60%, new 0.33, network alone 0.27, probe 21/32 with memory and 24/32 with the similarity gate; full-length run with the similarity as a trust-head input: stored 0.91 / 68% exact, new 0.33, network alone 0.29 (the best Q&A numbers), chat probe 21/32; the short run with the hard 0.5 gate stays the best chat configuration (24/32).
Pass: one checkpoint and one result file every later stage compares against.
B1
Partial-cue recall. Learned key built; needs in-domain training pairs.
Pass: probe reworded + synonym sections at least 4/5 each; verbatim unchanged.
B2
First skill circuit. Revised 17 Oct: a reading-documents adapter on the frozen 50M / 100M core (maths paused; documents are the largest open gap), trained with the whole mix replayed, against the mixed-stage baseline at equal steps.
Pass: document questions above the mixed baseline; no suite front lower by more than two standard errors; adapter under 5% of core size. Fail: the skill returns to the mixture at a higher share (the measured fallback).
B3

Pass: router agrees with hand choice at least 90%; mixed-set accuracy within two points of hand routing; reply cost up less than 20%.
B4

Pass: at least 80% agreement with hand grading; practice on detected failures beats a random sample of equal size.
B5
Sleep. Consolidation of used memories with rehearsal, plus pruning to a size budget.
Pass: at least 70% of 500 added facts answered with memory off after one sleep; rewordings improved; old-knowledge probe not lower.
B6

Pass: no failed reply; latency within 10%; rollback restores previous answers exactly.
B7

Pass: on knowledge it holds, accuracy within five points of the larger model at a tenth of the compute per reply or less; plus the abilities the larger model lacks (instant facts, deletion, inspection).

Where it will not beat a large model, stated plainly. Open-ended reasoning about things it has never seen, broad world knowledge it was never given, and fluent long writing depend on a large slow learner. The design wins where knowledge can be stored, looked up, checked or routed to a skill: domain assistants, a company's documents, personal knowledge, devices without a data centre. B7 is designed to show the size of that share honestly.

Compiler v0 text to codes and back, exactly

Files

compiler/compiler_v0.py (reference: scan, fit, learn_pieces, Encoder, Dictionary), compiler/native/cv0.cpp (fast encoder, byte-identical), tests in compiler/test_compiler_v0.py.

ID layout:   0..255 = single bytes (fallback; 12 = form feed, used as the end-of-answer code)
             256 = CAP   257 = UPPER   258.. = dictionary entries in file order

scan(text):  units left to right, first rule that matches wins (bytes regex):
               " [A-Za-z]+"  |  "[A-Za-z]+"  |  " +(?= [A-Za-z])"  |  " +"  |  "\n+"  |  "\t+"  |  any single byte

fit(train_texts, vocab = 8192, phrases = 0, case_flags = off, min_count = 2):
  counts = occurrences of each unit of length >= 2 in the training text
  words  = each distinct unit as a list of single bytes, weight = its count (sorted, for determinism)
  repeat until (vocab - 258) entries exist:
      take the adjacent pair (a, b), len(a) + len(b) <= 32, with the highest total weight;
          a pair is keyed by at_start (it is at position 0 of its unit)
      stop if that weight < min_count
      new entry: "S" (start piece) if at_start else "C" (continuation piece), bytes a + b
      merge that pair everywhere it occurs with the same at_start
  dictionary file: header lines, then one "S\tbytes" or "C\tbytes" line per entry; hash = FNV-1a 64

encode(text): for each unit, greedy longest start piece, then longest continuation pieces, else single bytes
decode(ids)  = concatenation of each id's bytes   (lossless by construction)
ID file: 24-byte header (b"CV0I", version 1, id width, pad, dictionary hash, count) + little-endian ids

Dictionaries (all 8,192 IDs, 7,934 entries): best 5M model models/qa_best_5M_512.cv0d, hash b37cb297879faba2, fitted on mix_D3s_5M; 50M core hash ed69527ab278fbb0, fitted on mix_P50 (599 s); the first models' models/v0_8k_plain_corpus_v2.cv0d, hash 3febecd65a1a77ff.

10. How the model came to be

A short history of how the original research question turned into the model described above. Each step kept something and dropped something, and the reason was always a measured result. The full record is in archive/track1_v1_experimental/RESEARCH_HISTORY.md, docs/VERSION_1.md, docs/DESIGN_V2.md and docs/RUN_LEDGER.md.

Sep
The original question: compress text so a small model learns more. The hope was that a compact representation closer to meaning would give a smaller, faster, more accurate model. The early phases (V6 to V12) separated three ideas that had been treated as one: storage compression, input representation, and semantic compilation (turning language into explicit entities, roles and state changes).
Kept: the goal of a small local model, and the idea of a compiler between text and model. Learned: the strong gains came from explicit structure and exact execution, not from compactness.
V1
Semantic V1 (15 September): a parser and an exact executor. Controlled accounting and ordering text was parsed into typed events (919k-parameter parser, 346-parameter core) and answered by an exact executor, very accurately inside its narrow grammar.
Kept: exact tools beside the network (today's calculator) and strict checking. Learned: the language boundary is the main risk, and a narrow specialist does not become a general model.
8 Oct
Compiler v0: a deterministic, lossless text-to-codes encoder, the same in both directions, so the model is trained on codes and talked to through the same compiler. 112 MB/s in C++, byte-identical to the Python reference.
Kept: unchanged to this day; every model reads and writes only its codes.
9 Oct
The encoder ladder settles the compression question. Compiled words beat raw bytes by 8% and reply 2.5x faster, but match a standard tokenizer within 1%; phrase codes that shortened the text by 18% made the model 2.5-4% worse. A lossless encoder can change speed and stability, not information.
Changed: the compiler's job became giving stable keys, not compressing harder.
9 Oct
Knowledge in lookup structures. Exact count tables mixed in by a learned trust head (with leave-one-out counting) made the 0.8M model 10.9% better than the standard tokenizer, and a book added to the counts helped with no training: learning by reading.
Kept: the trust head, and the idea that knowledge can live outside the weights.
9 Oct
The first talking test fails, and the memory is born. A Q&A model gave the same answer to every question: the tables only see the last few codes, which are identical after "Assistant:". A question-keyed exchange memory answered 99% of stored questions, including ones added after training, but the network ignored it (0.13 F1), until a learned copy head let it carry the retrieved answer into its reply (0.13 to 0.48, then 0.62).
Kept: memory + copy head became the engine of the design (Design v2).
10 Oct
The GPU, and three corrections. On the RTX 3090: the table gain reversed with size (+10% at 0.8M, 0 at 4.7M, -1% at 19M), so tables left core training; a core trained on Q&A alone memorised it, so cores are trained on text first and adapted to Q&A after; and reading the chat transcripts exposed a data bug that had cut 6.6% of answers.
Changed: two-stage training; tables kept only as a reading store.
10 Oct
What the core reads. A deep dive found the core had learned from 1800s novels (82%) and Wikipedia markup (half of the rest), with no conversation and no evidence windows. Clean modern text, conversation, evidence pairs and worked math cut conversation error by 36% and raised evidence use from 23% to 35%. Then the Q&A stage turned out to erase those gains; a gentle recipe (core 1e-4, heads 1e-3, answers-only loss, an end-of-answer code, rehearsal) kept them, and a 512-code window that stopped cutting answers gave the best 5M model, confirmed on two seeds.
Kept: today's data and training recipes, and the core report card.
11 Oct
Reasoning practice and the first large core. Verified self-training (solve with the stored answer hidden, keep only answers the calculator confirms, train on them) raised new arithmetic problems from 2.5% to 4.0% in two rounds. The 50M core, trained 2.4 hours on 2.3 GB, cut prediction error by 27-55% across every kind of text and lifted reworded-question retrieval from 51% to 58%.
Next: the 50M Q&A stage, then this brain-inspired design: skill adapters, gap-driven practice, sleep, and live updating.

The thread through all of it: the original aim (small, fast, local, accurate, able to learn without retraining) never changed. What changed was the mechanism. Compression gave way to stable keys, keys gave way to a memory the network can read, and the network became a reader and composer of what memory and tools provide, which is what this design builds on.

Specification
